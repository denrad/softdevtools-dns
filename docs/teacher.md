# Подготовка и сопровождение: черновик для преподавателя

**Статус: план действий.** Ни один описанный workflow ещё не создан и DNS
через этот репозиторий не меняется.

## До открытия студентам

1. Провести пилот с двумя GitHub-аккаунтами и тестовыми поддоменами:
   Pages → Custom domain → CNAME → HTTP → проверенный HTTPS. Не подтверждать
   родительский `softdevtools.ru` в аккаунте преподавателя без проверки
   последствий для студенческих сайтов.
2. Реализовать и проверить валидатор без секретов, затем проверяющий скрипт
   для опубликованной страницы. Убедиться, что сообщение об ошибке понятно
   студенту и временное ожидание не выглядит как провал.
3. Реализовать идемпотентный деплой Cloudflare; проверить `dry-run`, отказ
   при конфликте и запрет изменения посторонних DNS-записей.
4. Защитить `main`: обязательный PR, review, актуальные успешные проверки и
   контроль изменений workflow/скриптов. Протестировать параллельные заявки
   на одно имя и изменение системных файлов через fork.
5. Выпустить отдельный Cloudflare API Token с правом DNS Edit только для
   `softdevtools.ru`; хранить его только в GitHub Actions Secrets или
   Environment Secrets. Не копировать значение токена в файлы и логи.
6. Просмотреть всю историю и файлы перед сменой видимости репозитория:
   секреты, ФИО, группы и контактные email не должны оказаться публичными.
   Открывать репозиторий студентам после успешного пилота и проверки.

## Во время выполнения

1. Сверить автора PR с отдельным закрытым реестром. Способ создания реестра
   пока обсуждается; возможен отдельный закрытый репозиторий. Публичный
   email GitHub для этого не подходит как обязательный идентификатор.
2. Проверить свободное имя, соответствие `target` и репозитория сайта,
   результат CI и отсутствие изменений рабочих файлов.
3. Принять только проверенный PR. После merge проверить результат workflow
   деплоя и фактическую запись в Cloudflare. Ошибку деплоя не считать
   ошибкой студента без разбора причины.
4. Для очной части принять DNS и нужную страницу по HTTP/HTTPS. Сертификат
   и `Enforce HTTPS` могут появиться позже; повторная автоматическая
   проверка должна довести статус до конца.
5. Оценивать отдельно объяснение студентом цепочки публикации. Автоматический
   статус не равен оценке.
