# Лабораторная работа №5: сайт на собственном поддомене

**Статус: черновик инструкции.** Пока этот репозиторий закрыт, выполнять шаги
с PR нельзя.

## Результат

Простая страница из вашего публичного репозитория открывается по адресу вида
`https://student.softdevtools.ru`. Вы можете объяснить путь: репозиторий →
GitHub Pages → DNS-запись CNAME → HTTP-запрос → страница. Подробное устройство
TLS-сертификатов будет отдельной темой.

Оформление не оценивается. Достаточно одной страницы с заголовком, коротким
текстом и отличительным признаком: вашим выбранным поддоменом или GitHub-логином.
Можно использовать `index.md` или `index.html`, готовый шаблон и генератор
текста/кода. Не размещайте на странице ФИО, группу, телефон или личный email,
если не хотите делать их публичными.

## Предполагаемый порядок

1. Создайте публичный репозиторий со страницей `index.md` или `index.html`.
   Включите GitHub Pages и убедитесь, что страница доступна по исходному адресу
   GitHub Pages.
2. Выберите свободный одноуровневый поддомен в `softdevtools.ru`.
3. После открытия этого репозитория для студентов сделайте fork, добавьте один
   файл заявки в `records/` и откройте PR. Автоматическая проверка подскажет,
   если имя или формат неверны.
4. Укажите **то же имя** в `Settings → Pages → Custom domain` репозитория с
   вашим сайтом. Этот шаг нужно выполнить до создания DNS-записи.
5. Преподаватель сверит заявку с закрытым реестром и примет PR. После этого
   автоматизация создаст DNS-only CNAME. До принятия PR поддомен не выделен.
6. Проверьте DNS и страницу. Позже проверьте HTTPS без обхода проверки
   сертификата и включите `Enforce HTTPS`, когда настройка станет доступна.

Пример будущей заявки `records/ivan.yaml`:

```yaml
subdomain: ivan
type: CNAME
target: ivan123.github.io
repository: https://github.com/ivan123/my-lab-site
```

В `target` пишется имя `username.github.io` без `https://`, пути и названия
репозитория. Этот формат предварительный: окончательные правила определит
реализованный валидатор.

## Проверка во время занятия

После появления записи можно посмотреть её и запросить страницу по HTTP:

```sh
dig +short CNAME ivan.softdevtools.ru
curl -i --max-time 10 http://ivan.softdevtools.ru/
```

Если HTTP перенаправляет на HTTPS, это видно по коду ответа и заголовку
`Location`. Команда `curl -k https://...` допустима только как диагностика:
она пропускает проверку сертификата и не подтверждает готовность HTTPS.
Проверка результата должна увидеть **ваш отличительный текст**, а не только
код ответа `200`.

DNS обычно становится виден через несколько минут, но кеширование может
замедлить проверку. Выпуск сертификата GitHub Pages может продолжаться дольше
практической части. Для лабораторной предусмотрен статус ожидания и повторная
проверка после занятия.
