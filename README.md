# Учебные поддомены softdevtools.ru

Этот репозиторий готовится для лабораторной работы №5 по лекции №6 курса
«Инструментальные средства разработки программного обеспечения». Студент
публикует простую страницу на GitHub Pages, предлагает поддомен вида
`student.softdevtools.ru` через Pull Request (PR) и проверяет, как DNS связывает
имя с сайтом.

**Статус: проектная документация.** Репозиторий пока закрыт. Приём студенческих
PR, автоматические проверки и запись в Cloudflare ещё не реализованы. Перед
публикацией для студентов нужны пилот на двух GitHub-аккаунтах, реализация
проверок и просмотр всех файлов на предмет закрытых данных.

## Что здесь описано

- [Порядок выполнения лабораторной](docs/student.md) — будущая инструкция
  студенту и минимальные критерии результата.
- [Технический проект](docs/design.md) — формат DNS-заявки, проверки и границы
  автоматизации.
- [Порядок подготовки и сопровождения](docs/teacher.md) — будущие действия
  преподавателя и открытые вопросы пилота.

Исходная рабочая спецификация хранится отдельно. Документы здесь отражают
последующее обсуждение: GitHub Pages вместо Teletype; `index.md` **или**
`index.html`; минимальная страница без требований к дизайну; HTTP как
промежуточная проверка и отдельное подтверждение HTTPS.

## Границы репозитория

После подготовки здесь будут храниться только инструкции, технические заявки
на CNAME и код проверок/применения DNS. Секрет Cloudflare должен находиться в
GitHub Actions Secrets, иметь право DNS Edit только для `softdevtools.ru` и
использоваться только после принятия PR в защищённую ветку. Наличие секрета в
GitHub Actions **не делает код безопасным само по себе**: перед открытием
репозитория нужны защита ветки, контроль workflow и проверка содержимого.

ФИО, группы, контактные email, ответы закрытой формы и список соответствий
«студент ↔ GitHub-аккаунт» здесь не хранятся. Вариант отдельного закрытого
реестра остаётся задачей на обсуждение в методическом репозитории курса.

## Планируемая структура после реализации

```text
records/             одобренные заявки на поддомены
scripts/             проверка заявок, применение DNS, проверка сайта
.github/workflows/    проверки PR и действия после принятия
docs/                инструкции и технические решения
```

Сейчас этих рабочих каталогов и процессов нет; добавлять заявки студентов
рано. Методические решения и оценивание лабораторной остаются в закрытом
репозитории курса, а не в этом техническом репозитории.
